# Cabinet screen interaction

This follow-up is based on the sliding-door draft, commit `074e76b1b70bc61a25ac1709c0286a3af7fe4cc5` (PR #46), itself based on live main `0c771736020c8e21135b3342b4f67be6741b038d`. Merge and rendered QA remain held for parent coordination.

Inspecting a cabinet pauses the Arcade loop and frames that cabinet's actual screen. Native Play, Guide, Back and cabinet-selection controls occupy the screen opening. The scene supplies only a functional `screen` anchor: centre, normal, up, width/height and corners. These values follow the cabinet transform and tilted screen frame; there is no duplicate placement table in the app. Cabinet spacing, lettering, signs, plants and benches belong to the separate art task and have no changes here.

Play opens one iframe at the existing catalog URL on the same screen. Games retain their own documents, code and origin storage; game progress is not read, rewritten or copied by Arcade. No sandbox-origin change or camera/microphone/autoplay permission is introduced. All four published pages returned HTTP 200 with no X-Frame-Options or CSP frame restriction during the CPU implementation check. This confirms availability of the documents, not successful real-game play.

The Arcade renderer has no animation callback while a game is open; a paused resize can redraw the static cabinet framing. Back removes the game document and restores the saved aisle pose. Selecting another view, hiding the page or leaving removes the frame and its listeners. A hidden page returns to the selected cabinet menu without drawing another scene frame. Unsaved in-game state depends on each game's own lifecycle; the tab does not silently keep an unseen game running. Open full page and Guide retain the existing disposal-before-same-tab-navigation path. Modified Play clicks retain ordinary full-page link behavior, and the directory retains its new-tab links.

Back requests pointer lock during its trusted click, where supported. Escape returns to the aisle without attempting to override the browser's deliberate mouse release. After either action, mouse movement over the scene looks around immediately even if pointer lock is unavailable; drag look remains available, and a scene click can request locked look. Touch still requires deliberate drag. Keyboard movement, native navigation and Back remain available. Published same-origin game documents receive a scoped Escape handler; cross-origin local game ports use Back, and browser-reserved Escape/fullscreen behavior still requires rendered verification.

CPU evidence: the full `npm test` suite passes. Real Three.js geometry/controller checks cover all six cabinet screen anchors at 1280×720, 390×844 and 800×390: plane alignment, actual screen aspect, viewport margins, original aisle pose and zero scheduled render frames. Event-surface checks cover single-frame replacement, same-origin Escape, repeated Escape, modifier links, trusted Back capture, unlocked mouse look, touch exclusion, pagehide/hidden/help/directory cleanup and full-page disposal. Original source/vendor/archived-version and canonical handoff checks still pass. Scene structural counts remain those of the door draft; no meshes, textures or lights were added for the screen anchors.

Independent review found a child WindowProxy cleanup bug after a game redirects cross-origin. Cleanup now clears the listener reference before accessing the child and still removes the frame if that access fails. CPU tests cover redirects both on load and directly during Back. Independent SecurityError reproductions confirmed the fix, and final review found no additional material defects.

Pending: parent-authorized rendered QA of actual screen borders and menu scrolling, the real four games and their storage/controls, resize and touch, native browser Escape/pointer lock/fullscreen, both sliding exits and the homepage round trip. The prepared browser fixtures use stub destinations and are parsed by `npm test`; no browser, GPU, server, benchmark or deploy was started for this follow-up. These CPU checks establish functional and structural behavior, not FPS, GPU smoothness or absence of visual regression.
