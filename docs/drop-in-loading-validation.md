# Direct Arcade entry and loading validation

Status: draft follow-up to live main `3c01eb52876053f91fbb4ee014824fb2665734e2`. Parent coordinates publication. No merge or deployment is authorized for this follow-up yet. No Lab, Library, game, benchmark entry or archived-version content changes.

The former welcome panel and mandatory Explore button are removed. Successful preparation enters movement directly; a stored game-return selection still opens its cabinet actions. Instructions are available through Controls and Escape. Primary scene clicks request pointer lock; loading, focus recovery and closing help leave the mouse free. Help/inspection consumes Escape before controller handling, and held Escape cannot toggle panels repeatedly. Delayed pointer-lock grants invalidated by pause/dispose are released, including after a fresh keyboard session resumes.

The proposed common loading language uses background `#111214`, destination text `#f4f4f5`, stage text `#9b9da4`, and four 2 px segments (`#303238` pending, `#858991` current, `#d7d9df` complete). The destination label is 20 px system text; stage labels are 12 px. Only actual stage completion advances the indicator: Loading engine, Building scene, Preparing graphics, Opening Arcade, then Ready. No percentages, elapsed-time estimates or decorative progress animation are used. The lightweight component is local and has no additional dependencies.

The loading cover is in initial HTML, before code runs. Two frame opportunities per stage let updated labels paint before synchronous work. The controller must complete its first render before readiness; the cover then fades in 180 ms, with a 200 ms hide timer. Reduced motion disables the fade and timer. Starting a new load cancels prior fade work and displays an immediate opaque cover. Same-tab navigation covers the canvas before disposal, cancels every loading frame/timer, releases in-flight renderer/world ownership, then leaves. Import cancellation cannot construct resources after navigation. Cached-page restoration starts one new controller. Opening Games or Controls during preparation cancels that preparation; returning to the scene safely restarts it.

Loading status is a polite atomic live region; the scene exposes `aria-busy`. The indicator is decorative and hidden from assistive technology. Errors expose an accessible game directory with Retry loading, Home and existing game links. Retry reloads after disposal to permit another fetch following a failed module import. Help and the canvas are keyboard focusable; native links and game-return state remain intact.

`npm test` passes the full catalog, session, navigation, geometry, collision, controller, new loading lifecycle, saved-version hash and browser-fixture syntax checks. The loading tests execute the shipped application orchestration against manually advanced CPU frame/timer queues and stub rendering surfaces. They cover automatic keyboard entry without capture, real stage ordering, reduced motion, stale fade cancellation, import/renderer/compile/first-render failure, accessible retry, cancellation while importing or preparing graphics, cancellation after controller creation, Games return, cabinet return and cached-page restoration. Controller tests exercise primary-click capture, right-click exclusion, delayed grant invalidation after pause/dispose/resume and repeated/consumed Escape. These checks do not measure graphics behavior.

Independent static review found delayed pointer-lock grants and repeated-Escape toggling; both were fixed and independently rechecked. No material findings remain. Browser fixtures were updated for direct entry and help behavior, but no browser test has run under the resource hold.
