# Private cabinet input correction

This branch follows Jordan's explicit interaction correction. It is CPU/source-ready and unshipped. The earlier functional reference remains on `craft/cabinet-screen-lifecycle` at `0b6e4a4e59cfcdc9f3973bdb4fae5def3db73520`; its menu artwork was rejected. No menu bitmap, course illustration, token asset or cabinet art was redesigned here. Replacement visual direction belongs to designer `01a1229d-d0ce-7010-adb3-27c7b5eab0fb` and is still pending.

An unlocked primary cabinet press now selects it before any pointer-lock request. A captured press uses the existing centre ray and releases scene lock. Natural click/E selection preserves the complete player position, eye, yaw, pitch and lens. Explicit directory approaches retain their existing standing approach/aim. Cabinet interaction pauses walking/look input and lets the cursor use the projected screen's native controls.

The viewport cabinet browse/game toolbars have been removed from HTML. Website navigation is hidden and inert throughout inspection, insertion and play. Normal title choices and Back/Cancel remain on the physical screen. Generic Guide and delayed/error recovery controls now belong to that same plane. Loading focus uses its Cancel/Back target rather than a removed toolbar. RaceGPT's existing loading/error artwork remains unchanged; its live announcement is visually clipped. The playable game viewport is retained without surrounding bars, using the same child document across resizing. The previous Fit toolbar control is absent from this correction.

A capture-phase primary press outside the current screen, game viewport or selected cabinet envelope cancels/removes the active launch and returns to the aisle. It is consumed before reaching the resumed canvas, preventing a second activation from the same press. Cabinet envelopes are CPU metadata captured before static scene merging and checked with the existing opaque-geometry occlusion rules; no render meshes were added. Actual physical buttons remain future optional targets, not new artwork or bindings in this patch.

A trusted outside press or physical Back click can request scene pointer lock inside the same gesture. Free window mouse look resumes immediately even when the browser rejects or lacks locking. Programmatic entry unlocks and stale grants are distinguished from browser-owned unlocks; a late entry unlock cannot reopen help after the aisle has resumed.

Delivered Escape exits without requesting pointer lock. The paired RaceGPT bridge routes Escape keydown, or keyup when keydown was consumed, through its existing verified back message after the selected run has started. Standalone RaceGPT retains its normal pause behavior. Browsers may reserve Escape for pointer-lock release and withhold events; this patch cannot bypass that. If no Escape event reaches a cross-origin game or parent, the visible room margin provides the outside-click exit. Generic cross-origin games without the paired bridge use the same outside-click fallback. The patch does not promise seamless capture when browser gesture/cooldown restrictions prevent it.

Focused CPU evidence covers unlocked/locked cabinet entry, complete pose preservation, cabinet body/marquee bounds and occlusion, rejected/stale/late pointer-lock paths, projected menu focus and Back gesture forwarding, all three cabinet-mode outside exits, late document cancellation, error/retry, same-document resize, verified native Escape with repeat suppression and standalone scope. Host `npm test`, native bridge tests and native TypeScript/build checks pass. The bounded review harness was updated and parsed only. No browser, game runtime, renderer, server or GPU session was launched for this correction; rendered input acceptance requires a new parent clearance. Earlier screenshots and review receipts describe the frozen candidate and do not validate this correction.

The native pair is in `../racegpt-cabinet-bridge`, branch `craft/cabinet-input-exit`, based on frozen `72816f6d75b286090976bac827191bbb269e581a`. The version1 ready/start/started/menu/back message envelope and source/origin/session/track checks remain unchanged. Native Escape adds no new network authority or message shape.
